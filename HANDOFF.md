# Amado — HANDOFF.md

Read this first in a new conversation, then read `docs/AMADO_ROADMAP.md` for full sprint-by-sprint detail and `docs/SCHEMA.md` for the database.

## What this is

Amado — B2B-маркетинг AI-платформа для команды, продвигающей бренд на бразильском рынке.

- **UI-язык:** русский (интерфейс, аналитика, внутренние выводы ИИ — например "почему это важно" в брифинге, гипотезы по перформансу)
- **Язык контента:** pt-BR (сгенерированные статьи/посты для бразильской аудитории — это не то же самое, что UI-язык; не путать)
- **Стек:** Next.js 16 (App Router), React 19, TypeScript strict, Supabase (pgvector), Tailwind 4, Vercel AI SDK v6, Vitest, Playwright (не запускался)
- **AI-провайдеры:** Google Gemini → Groq → OpenAI → DeepSeek, фолбэк-цепочка с quota-cooldown (`lib/ai.ts`)
- **Репозиторий:** `paalverteller/amado`, ветка `main`, прямые коммиты (без PR)

## Как здесь ведётся разработка (важно для новой сессии)

- **Формат поставки:** Python-скрипт с `--check/--apply/--verify/--commit/--push`, содержимое файлов зашито внутри скрипта (полная перезапись, не патчи — так безопаснее и соответствует принципу «файл пишется целиком»).
- **Все команды в ответе — через `&&`**, не построчно: упавший `--verify` должен реально блокировать `--commit`. (Однажды это не было соблюдено — два коммита с падающим `tsc` ушли в `main`.)
- **Перед доставкой — реальный тест-цикл**, не просто «код выглядит правильно»: развернуть копию репо в песочнице, сбросить к чистой базе (`git reset --hard` / `git checkout HEAD --`), прогнать `--apply → --verify → --apply снова (идемпотентность) → --commit → --commit снова (тоже идемпотентно)`. Несколько реальных багов было поймано именно так, а не угадыванием.
- **Один спринт — один консолидированный скрипт**, не несколько с пересекающимися файлами. Один раз два скрипта Sprint 5 независимо переписывали `lib/rss.ts` целиком — какой применился последним, тот и победил, второй потерялся молча. Если правка требует несколько частей — либо один скрипт на всё, либо чётко предупреждать о порядке и рисках.
- **Обновления `docs/AMADO_ROADMAP.md` — коммить explicit'но**, отдельной командой `git add docs/AMADO_ROADMAP.md && git commit`, не полагаясь на то, что следующий спринт-скрипт подхватит их через `git add -A`. Это уже один раз привело к потере обновлений за спринты 4, 5, 6, 10 — они существовали только в рабочем дереве и были случайно стёрты позже при `git reset --hard` во время тестирования хотфикса. Восстановлены и закоммичены явно 2026-08-11.
- **Next.js 16: файл называется `proxy.ts`, не `middleware.ts`.** Это переименование внутри Next 16 — в проекте уже был готовый `proxy.ts` с рабочей авторизацией ещё до начала этой переписки; я его не заметил в Sprint 10 и создал конфликтующий `middleware.ts`, что сломало сборку (`next build` явно ругается, если есть оба файла). Смотреть на реальный `next build`, не только `tsc --noEmit`, — вот что должно было поймать это раньше.
- **`npm run build` — часть `--verify`, не только `tsc`/`lint`.** Конфликт proxy/middleware `tsc` не ловит вообще.

## Что осознанно не сделано (не забыть, не блокирует)

- **`/api/cron/auto-generate`** — легаси-крон из до-пивотного психологического продукта, до сих пор активен в `vercel.json` (06:00 UTC), ежедневно пишет случайную сгенерированную статью в `articles` из `book_chunks`. Ждёт твоего решения — выключать или нет.
- **`handsoff.md`** в корне репо — отдельный документ для ChatGPT-сессий, описывает нереализованный "Sprint 5 — grounded generation", которого нет в реальном коде. Не трогал, но при желании стоит обновить или удалить, иначе кто-то откроет по нему ChatGPT-сессию и получит рассинхрон с `main`.
- **`app/api/generate/batch/route.ts`** (пакетная генерация) — не подключён к новому `buildBrandSnapshot`/`buildKnowledgeContext` из Sprint 8, использует старый `buildBrandVoiceLayer`.
- **`content_pattern_usage`** (hook_type/structure_pattern и т.п. из миграции 036) — не подключена, нужна отдельная UI-таксономия разметки контента.
- **Реальное разделение workspace/пользователей** — нет модели сессий вообще, один общий пароль (`ACCESS_PASSWORD`). Осознанно не изобретал внутри hardening-спринта.
- **E2E-тест** (`e2e/core-journey.spec.ts`) — написан по реальным селекторам, ни разу не запускался (в песочнице не было живого стенда/Supabase/ключей ИИ).
