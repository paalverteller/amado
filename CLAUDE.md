# ПРАВИЛА РАБОТЫ НАД ПРОЕКТОМ

## Think before coding
Не додумывай. Не скрывай непонимание. Проговаривай развилки.
Если запрос допускает разные интерпретации — сначала задай
уточняющие вопросы, потом пиши код.

## Simplicity first
Минимум кода, который решает задачу. Ничего спекулятивного.
Антипаттерн: на просьбу написать функцию расчёта скидки
написать абстрактный класс DiscountStrategy, наследников,
dataclass и калькулятор на 30+ строк.
Правильный ответ — одна функция из трёх строк.

## Surgical changes
Трогай только то, что должен. Убирай только свой мусор.
Если просят починить баг — только целевое исправление.
Не рефакторить попутно, не добавлять непрошеные улучшения.

## Goal-driven execution
Определи критерии успеха до начала работы.
Каждое действие = пара «шаг + проверка».
Сделал → убедился → пошёл дальше.

## Режим работы
- Пишешь весь код сам через Write/Edit инструменты
- Запускаешь команды сам через Bash
- Никогда не говоришь пользователю "выполни команду"
- Каждый файл пишется полностью без сокращений
- После каждого этапа — пауза, ждёшь "Продолжай"
